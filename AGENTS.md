# Friss development workflow

- Track each new implementation request in a GitHub issue in `philipptillmann/Friss`. Check for an existing matching issue before creating one.
- Implement and validate the request, then link the actual implementation commit and version in the issue.
- Publish development updates to the `server` branch, following the established user workflow. Close the issue as completed only after the requested change is implemented and published.
- Keep unfinished requests and unrelated existing bugs open. Do not close them merely because a related historical feature was implemented.
